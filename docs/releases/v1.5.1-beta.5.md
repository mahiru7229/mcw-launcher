# MCW Launcher v1.5.1-beta.5

Beta 5 hardens the updater introduced in Beta 3/4 after Windows testing still reproduced `WinError 5` while replacing `MCW Launcher.exe`.

## Updater

- The Windows updater now waits for the primary launcher PID **and** any remaining process whose full image path matches the current installation's `MCW Launcher.exe`.
- Before the transaction starts, the updater probes Windows DELETE/replace access to the launcher executable. This catches lingering PyInstaller/security-scanner file handles even when no matching process is visible.
- The updater refuses to mutate the installation if the launcher executable remains locked after the release timeout.
- Executable replacement still happens before all other files and keeps atomic replace retry + rollback safety.
- `MCW Updater.exe` now has a branded standalone GUI with the MCW logo, target version, phase/status text and deterministic progress states.
- The launcher READY handshake and fallback to an installed updater remain in place.

## Recovery

- Emergency `MCW-USE-BRIDGE` routing remains maintainer-controlled.
- MCW Update Bridge is moved to v1.4.0 with Beta 5 as its default recovery target.
- Bridge CI keeps LF-only checksums, CRLF normalization during verification and explicit `--repo` release uploads.

## Packaging

- `docs/` remains excluded from user release ZIPs.
- `cleanup_paths: ["docs"]` remains in the release manifest so old bundled docs are removed silently when present.
- The updater spec bundles the MCW PNG/ICO assets required by its standalone GUI while continuing to exclude PySide6/Qt.

## Validation focus

The critical live migration test for this beta is `v1.5.1-beta.4 -> v1.5.1-beta.5` on Windows while observing `logs/updater.log`. A successful run should show the primary launcher process exiting, the installation becoming fully stopped/unlocked, executable replacement, and the new launcher starting without `WinError 5`.
