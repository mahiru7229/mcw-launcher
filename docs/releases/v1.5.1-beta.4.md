# MCW Launcher v1.5.1-beta.4

Beta 4 completes the updater-v2 migration.

## Update handoff

- Release ZIPs carry a dedicated updater from the incoming release.
- On Windows the updater has its own lightweight GUI.
- The launcher remains open until the incoming updater writes its READY handshake.
- If the incoming updater cannot initialize, MCW tries the updater already installed on the machine as a fallback.

## Recovery override

Attaching Bridge binaries alone does **not** change normal update behavior. To explicitly force recovery for a broken release, the maintainer also uploads an asset named `MCW-USE-BRIDGE`. The launcher then downloads the platform Bridge, verifies its SHA-256 sidecar, and hands the update to the Bridge automatically.

## Release cleanup

`docs/` is no longer shipped in end-user release ZIPs. The package manifest declares `cleanup_paths: ["docs"]`; updater and Bridge remove that path if present and silently skip it if absent. Source/repository documentation remains in Git.

## Mod dependency recovery

Launcher-managed `required_dependency` Modrinth artifacts are re-downloaded when their tracked hash is stale instead of being preserved as user-modified files. This addresses the Cloth Config dependency loop observed in diagnostics.
