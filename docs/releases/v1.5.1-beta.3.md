# MCW Launcher v1.5.1-beta.3

**Release type:** Beta  
**Date:** 2026-09-09

## Summary

Beta 3 replaces the legacy self-updater bootstrap with **Updater Architecture v2**. Release ZIPs now carry a dedicated updater executable built from the target release. The currently installed launcher only downloads and validates the package, copies the incoming updater to a temporary directory, starts it, and exits.

This change is intended to permanently remove the failure mode discovered in v1.5.0 where the launcher copied its own executable and reused old updater code while trying to install a newer release.

## Updater Architecture v2

Windows release package:

```text
MCW-Launcher-v1.5.1-beta.3-windows-x64/
├── MCW Launcher.exe
├── mcw-update.json
├── updater/
│   └── MCW Updater.exe
├── lang/
├── themes/
├── docs/
├── README.md
└── LICENSE
```

Linux release package:

```text
MCW-Launcher-v1.5.1-beta.3-linux-x64/
├── mcw-launcher
├── mcw-update.json
├── updater/
│   └── mcw-updater
└── ...
```

`mcw-update.json` now uses schema version 2 and must declare the bundled updater. Packages without the expected updater are rejected before the current installation is modified.

## Update handoff

From Beta 3 onward, the intended transition is:

```text
Installed Beta 3
  → download/extract Beta 4 ZIP
  → validate schema 2 + SHA-256
  → copy Beta 4 updater from ZIP to system temp
  → start Beta 4 updater
  → close Beta 3 launcher
  → Beta 4 updater replaces launcher files
  → restart Beta 4
```

There is **no fallback** to copying the current `MCW Launcher.exe` / `mcw-launcher` as an updater.

## Windows v1.5.0 recovery

Existing v1.5.0 installations that need recovery can use **MCW Update Bridge v1.2.0** on Windows x64 or Linux x64 once to install Beta 3 directly. After migration, normal automatic updates use Updater Architecture v2.

## Build changes

- Added `updater.py`, a dedicated updater entry point with no GUI dependency.
- Added `mcw_updater.spec` for Windows/Linux updater binaries.
- Release workflow now builds launcher + updater independently on each platform.
- `tools.build_release_zip` now requires `--updater` and emits schema-2 packages.
- Windows package contains `updater/MCW Updater.exe`.
- Linux package contains `updater/mcw-updater` with executable mode encoded in the ZIP.
- Local `build_release.ps1` builds both binaries before packaging.

## Safety carried forward from Beta 2

- Launcher executable is replaced before remaining managed files.
- Windows executable replacement retries transient file locks for about 30 seconds.
- Rollback skips files that were never changed.
- Launcher is not restarted when rollback cannot complete safely.

## Validation target

The critical live test for this release is **Beta 3 → Beta 4**. Passing that transition proves the launcher is executing updater code supplied by the new release rather than updater code embedded in the currently installed launcher.
