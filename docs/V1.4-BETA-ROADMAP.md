# MCW Launcher v1.4 — Three-Beta Roadmap

## v1.4.0-beta.1 — Task lifecycle & runtime safety

- TaskRunner v2 foundation: cooperative cancellation, replaceable background/network work, shutdown cancellation boundary.
- Launcher close prioritizes launcher shutdown and does not wait for disposable background work.
- Running Minecraft processes remain alive when the launcher closes by default.
- Instance Workspace **Kill Instance** action with confirmation and supervised force-kill semantics.
- User-killed sessions are not classified as crashes.
- Fix Forge issue #20: strict profile selection, validate-before-cache, poisoned-cache invalidation.
- Retain v1.3.2 issue #19/atomic-write/update-integrity hardening.

## v1.4.0-beta.2 — Modpack performance & update priority

- **Update Priority Mode**: cancel unrelated launcher work, reject new non-update tasks, drain safe checkpoints, then prepare/apply the update.
- Adaptive parallel download for Modrinth `.mrpack` managed files.
- One-pass SHA-1/SHA-512/SHA-256 verification with a conservative hash I/O budget.
- Progress coalescing retained and download-journal progress writes batched to reduce UI/disk contention.
- **Automatic / Responsive / Balanced / Maximum** performance profiles.
- Automatic low-impact download concurrency while Minecraft is running.
- Mutation-heavy per-instance content changes intentionally remain serialized for safety.
- Deeper streamed-hash reuse/resource-aware mutation scheduling is deferred unless beta benchmarks justify it.

## v1.4.0-beta.3 — Diagnostics & release hardening (implemented)

- Diagnostics v2 bundle with launcher/runtime/loader logs, hardware/configuration, task timeline and relevant instance state.
- Robust collector isolation, log size limits and centralized secret/path redaction.
- **Create Issue Report** workflow and GitHub issue template generation.
- Loader/runtime integrity context, including Forge installer/profile/cache diagnostics.
- Task Center polish, stale-result/error UX review, benchmarks and Windows soak testing.
- RC/stable readiness pass after all beta regressions are green.


## v1.4.0-beta.4 — Progress/state consistency (implemented)

- Global progress ownership prevents older concurrent tasks from overwriting newer task state.
- Profile-less tasks reset stale progress when they start and receive generic success/failure/cancel terminal states.
- Cancelled/superseded tasks run the same UI busy cleanup path as success/failure.
- Provider/dialog busy state is rebuilt from TaskRunner active tasks to stay correct across REPLACE generations.
- Legacy Storage probe, scan and cleanup expose explicit progress completion states.

## v1.4.0 — Stable

- Promotes the beta.1–beta.4 lifecycle, performance, diagnostics and progress-state work to the stable channel.
- Includes the beta.4 `ProgressStage` import/runtime hotfix and static regression guard.
- Publishes standalone MCW Core source and wheel artifacts again for stable consumers.
- No new feature scope is added during stable promotion; only release-blocking fixes discovered by validation are accepted.
